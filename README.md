# 💈 BarberGO

### Dupla 3 — Sistema de Agendamento para Barbearia

**Integrantes:** Vitor Chagas e Felipe Padilha

---

## 📋 Sobre o Projeto

A BarberGO é uma plataforma desenvolvida com HTML, CSS e JavaScript que tem como objetivo facilitar a rotina administrativa de uma barbearia.

O sistema permite cadastrar clientes, registrar serviços, realizar agendamentos e acompanhar o histórico de atendimentos através de uma interface moderna e intuitiva.

---

## 🎯 Objetivo do Sistema

Desenvolver uma solução simples para gerenciamento de barbearias, permitindo o controle de clientes, serviços, agendamentos e histórico de atendimentos, aplicando conceitos de desenvolvimento web aprendidos durante o curso técnico.

---

## 👥 Público-Alvo

O BarberGO foi desenvolvido para atender:

* Proprietários de barbearias;
* Barbeiros autônomos;
* Pequenos estabelecimentos que necessitam organizar seus atendimentos;
* Profissionais que desejam substituir controles manuais por uma solução digital simples e eficiente.

---

## 🚀 Funcionalidades

### 👥 Clientes

* Cadastro de clientes;
* Consulta de clientes cadastrados;
* Armazenamento local dos dados.

### ✂️ Serviços

* Cadastro de serviços oferecidos;
* Definição de preços;
* Gerenciamento de serviços disponíveis.

### 📅 Agendamentos

* Agendamento de horários;
* Seleção de cliente e serviço;
* Controle dos horários marcados.

### 📊 Histórico

* Visualização dos atendimentos realizados;
* Consulta de registros anteriores.

---

## 📌 Requisitos Funcionais

### RF01 – Cadastro de Clientes

O sistema deve permitir cadastrar e consultar clientes.

### RF02 – Cadastro de Serviços

O sistema deve permitir cadastrar serviços e definir seus respectivos preços.

### RF03 – Gerenciamento de Agendamentos

O sistema deve permitir criar, visualizar e organizar agendamentos.

### RF04 – Histórico de Atendimentos

O sistema deve permitir consultar atendimentos realizados anteriormente.

### RF05 – Armazenamento de Dados

O sistema deve armazenar as informações utilizando Local Storage.

---

## ⚙️ Requisitos Não Funcionais

### RNF01 – Usabilidade

O sistema deve possuir uma interface simples, intuitiva e de fácil utilização.

### RNF02 – Responsividade

O sistema deve adaptar-se a diferentes tamanhos de tela.

### RNF03 – Desempenho

As operações de cadastro e consulta devem ser executadas rapidamente.

### RNF04 – Compatibilidade

O sistema deve funcionar nos principais navegadores modernos.

### RNF05 – Disponibilidade

O sistema deve estar acessível através do GitHub Pages.

### RNF06 – Manutenibilidade

O código deve ser organizado para facilitar futuras atualizações e melhorias.

---

## 📖 Regras de Negócio

### RN01

Um agendamento somente poderá ser realizado para clientes previamente cadastrados.

### RN02

Todo agendamento deve estar vinculado a um serviço cadastrado.

### RN03

Todo serviço cadastrado deve possuir um preço definido.

### RN04

Os dados serão armazenados localmente utilizando Local Storage.

### RN05

O histórico deve registrar os atendimentos realizados para consulta posterior.

### RN06

Os registros permanecerão disponíveis enquanto os dados do navegador não forem removidos pelo usuário.
